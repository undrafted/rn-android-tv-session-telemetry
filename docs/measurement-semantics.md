### Measurement semantics

See also: [signals.md](signals.md) for the signal-flow diagram this detail belongs to.

| Topic                      | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Clocks                     | Monotonic-source only (`performance.now()` on the JS side; Android's own native clock for frame timing). Wall-clock (`Date.now()`) appears exactly once, in `ClockSyncEvent.wallClockUnixMs` — never used for duration math, only as one half of a (monotonic, wall-clock) correspondence pair for mapping a workstation-side bookmark onto the session's own timeline                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Units                      | Every `durationMs`/`timestamp` field is milliseconds; `sequence` is a per-session monotonic counter, not a wall-clock-derived id                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Sequence numbers           | Assigned by a single counter (`createSequenceCounter()`, `index.ts`) that lives for the JS engine's whole process lifetime — **not** reset by `install()`/`stop()`. Two back-to-back `install()` calls in the same app process continue the same counter rather than restarting at 0; only a true process restart (cold app launch) resets it                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Session boundary           | Bidirectional and independent: the app's own `SessionTelemetry.install()`/`.stop()` _and_ a workstation `session-telemetry record`/`stop` (ADB broadcast to `ACTION_START_SESSION`/`ACTION_STOP_SESSION`) can each open or seal the on-device native session. Whichever happens most recently wins — `startFreshSession()` (`SessionWriterModule.kt`) always seals whatever was open first, then opens a new one, so there's never more than one native session live at a time regardless of which trigger fired                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Native push ordering       | `SessionWriterModule.pushEvent()` is a silent no-op while `handle == 0` (no native session open yet) — confirmed as a real, 100%-reproducible bug: `install()` originally called `emitSessionMetadata()` _before_ `startNativeSession()`, so the baseline clock-sync and session-metadata events were dropped on every single session. Fixed by calling `startNativeSession()` first — RN's bridge dispatches calls to one native module in the JS-side call order, so this ordering is a real guarantee, not a lucky race                                                                                                                                                                                                                                                                                                                                                                                                               |
| Overhead benchmark         | Compares average per-call cost of `mark()` while the library is stopped (`installed = false`, an early-return no-op) against the same call while installed and actively recording, over a configurable iteration count — see [apps/tv-fixture/README.md](../apps/tv-fixture/README.md#overhead-benchmark) for the exact numbers and how to reproduce them (`npm run benchmark`, reads from logcat, not part of a recorded session's own data)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Event loss                 | `Chunk.manifest.lossCount` — always `0` today. Intended detection mechanism (not implemented yet): a gap in the decoded chunk's own `sequence` numbering would mean an event was dropped somewhere between the JS buffer and the sealed chunk; nothing currently scans for that gap. Disclosed in `analyze`'s output and `Report`/HTML regardless of whether it's ever nonzero, so the absence of loss detection doesn't silently read as "definitely zero loss"                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Clock uncertainty          | `ClockMap.uncertainty_ms` — the largest residual across fitted clock-sync samples, a bound on how far a mapped timestamp could be off. `ClockMap` fits both an _offset_ and a _scale_ (not just a constant offset), since two independent hardware clocks can drift relative to each other over a multi-hour QA session; a single sample can only anchor an offset (scale assumed `1.0`, `uncertainty_ms = 0.0`), two or more fit both via least squares. Surfaced two ways: per bookmark (`analyze`, HTML) and session-wide as `Report.clockUncertaintyMs` (JSON/HTML), `null` when the session had no clock-sync samples to fit from                                                                                                                                                                                                                                                                                                   |
| Storage budget             | Three independent limits, all in `SessionWriterModule.kt`, all unvalidated placeholders: a chunk rotates (seals and starts a new one) at `DEFAULT_MAX_CHUNK_BYTES` (256 KB) or `DEFAULT_MAX_CHUNK_DURATION_MS` (60 s), whichever comes first; the whole session (sealed chunks plus the in-progress one, combined) is capped at `DEFAULT_BUDGET_BYTES` (200 MB). Hitting the total budget stops the writer permanently for that session (`PushOutcome::BudgetExceeded`, `RotatingChunkWriter` in `session-telemetry-session`) — every event after that point is silently rejected, logged once (not per-event) via `Log.w`, and every chunk sealed _before_ the budget was hit remains intact and pullable. Recording never overwrites earlier evidence to make room                                                                                                                                                                     |
| React commit capture       | Wired (`<Profiler onRender={onProfilerRender}>`) but **not yet observed firing on a real device** — `reactCommitCount` has been `0` in every real trace recorded against the emulator so far. Detectors that depend on it (`react-commit-overlapping-delayed-frame`, `excessive-commits-during-rapid-focus-movement`, `unstable-selector-reference`'s commit-overlap condition) are therefore unverified against real hardware — confirmed as a real gap                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Network / JS stall capture | `createInstrumentedFetch`/`startStallMonitor` exist and are tested in isolation, but `apps/tv-fixture/index.js` doesn't call either — `networkCount`/`jsStallCount` are always `0` in any current fixture trace                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Native module registration | RN's autolinking discovers exactly one `ReactPackage` per npm dependency — it globs for `**/*Package.{java,kt}` and takes the first match (`findPackageClassName.js`, `@react-native-community/cli-config-android`). This library used to ship three separate package files (`FrameTimingPackage`, `SessionWriterPackage`, `GlobalFocusPackage`), so only the first was ever autolinked and the other two needed manual registration in a host app's `MainApplication.kt` — confirmed the hard way when `GlobalFocusModule`'s events silently never arrived in JS. Consolidated into one `RnSessionTelemetryPackage` (`createNativeModules` returns all three) so autolinking picks up everything on its own; a host app needs **zero** native code to link this library now — no import, no registration line. A future native module just needs to be added to that one package's `createNativeModules()` list, not a new package file |

### Signal capture mechanisms

How each signal actually reaches the session, grounded in the current source (not plan.md's boundary column, which describes the intended shape rather than the concrete call site).

| Signal             | Captured via                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Wired into the fixture app?            |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| Remote input       | `TVEventHandler.addListener` (`index.ts`), filtered by `isRemoteInputEventType`                                                                                                                                                                                                                                                                                                                                                                                                   | Yes                                    |
| Focus              | Zero-footprint: native `GlobalFocusModule.kt`, one app-wide `ViewTreeObserver.OnGlobalFocusChangeListener` (`startGlobalFocusMonitor()`), identifying the focused view via its standard RN `nativeID` prop (`view.getTag(R.id.view_tag_native_id)`) — no telemetry-specific wrapper component or `onFocus` handler needed, just `<Pressable nativeID="card-1">`. Forwards to the unchanged `SessionTelemetry.recordFocus()` (still owns sequencing/timestamps/`previousTargetId`) | Yes                                    |
| Visible update     | Same native listener — `newFocus.post { }` (posted to that view's own UI-thread message queue, running once the current layout/draw pass settles) right after the focus notification, forwarded to the unchanged `SessionTelemetry.recordVisibleUpdate()`. Tied to Android's real message queue rather than a JS-side `requestAnimationFrame` guess, but still best-effort, not a hard guarantee of the exact composited frame                                                    | Yes                                    |
| Interaction marker | `SessionTelemetry.mark()` — explicit app call                                                                                                                                                                                                                                                                                                                                                                                                                                     | Yes (`onPress`)                        |
| Redux dispatch     | `createTelemetryMiddleware` (`packages/redux`)                                                                                                                                                                                                                                                                                                                                                                                                                                    | Yes                                    |
| Redux selector     | `telemetrySelector()` wrapper (`packages/redux`) — transparent passthrough (calls the real selector exactly once, returns its exact result, so it can't affect the wrapped selector's own memoization). `inputsChanged`/`resultChanged` compare this call's arguments/result against the _previous call's_ by `Object.is` per argument position, never by value — the first call ever has nothing to compare against, so both flags read `true`                                   | Yes                                    |
| Network request    | `createInstrumentedFetch` — wraps `fetch`, app must pass the wrapped version through                                                                                                                                                                                                                                                                                                                                                                                              | No                                     |
| JS stall           | `startStallMonitor` — schedules a `setTimeout` at `intervalMs` (default **50ms**) and flags it as a stall when it fires more than `thresholdMs` (default **50ms**) late; a symptom of the main thread being blocked, not real CPU profiling                                                                                                                                                                                                                                       | No                                     |
| React commit       | `<Profiler onRender={onProfilerRender}>` — React's public Profiler hook                                                                                                                                                                                                                                                                                                                                                                                                           | Yes, but see the capture-gap row above |
| Frame timing       | Native `FrameTimingModule.kt`, `Window.OnFrameMetricsAvailableListener` (`FrameMetrics.TOTAL_DURATION`); only frames exceeding `thresholdMs` (default **32ms**, roughly one dropped 60Hz frame's worth) cross the bridge to JS at all                                                                                                                                                                                                                                             | Yes                                    |
| Clock sync         | Periodic, piggybacked on whichever event happens to push next — `CLOCK_SYNC_INTERVAL_MS` = **30,000ms** since the last sample — plus once unconditionally as the very first push after `install()`                                                                                                                                                                                                                                                                                | Yes                                    |
| Session metadata   | Once, at `install()` — `deviceModel`/`osVersion` from React Native's `Platform` module; `appVersion`/`buildType` only if the app supplies them via `InstallOptions`                                                                                                                                                                                                                                                                                                               | Yes                                    |

### Signal → detector/consumer

What actually reads each signal once it's in the session. "Evidence only" means no detector consumes it directly, but it still appears in a finding's evidence timeline if it falls within that finding's sequence range.

| Signal             | Consumed by                                                                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Remote input       | Anchors every `InteractionWindow` (`build_interaction_windows`)                                                                                                  |
| Focus              | `high-latency-focus-change`                                                                                                                                      |
| Visible update     | `high-latency-visible-update`; also ends an interaction window's scan                                                                                            |
| Interaction marker | Evidence only                                                                                                                                                    |
| Redux dispatch     | `repeated-redux-dispatch`                                                                                                                                        |
| Redux selector     | `repeated-selector-recomputation`, `unstable-selector-reference`, and `Report.selectorStats` (session-wide aggregate, independent of any detector)               |
| Network request    | `repeated-network-request`, `network-completion-followed-by-commit`                                                                                              |
| JS stall           | `js-stall-during-interaction`                                                                                                                                    |
| React commit       | `react-commit-overlapping-delayed-frame`, `excessive-commits-during-rapid-focus-movement`, `unstable-selector-reference` (its required commit-overlap condition) |
| Frame timing       | `react-commit-overlapping-delayed-frame`                                                                                                                         |
| Clock sync         | `ClockMap` → `Report.clockUncertaintyMs` and bookmark mapping — not read by any detector                                                                         |
| Session metadata   | `Report.deviceMetadata` (first matching event only) — not read by any detector                                                                                   |

Detector thresholds (`session-telemetry-analysis::detector`) — all placeholders pending real
device measurements, not values anyone has validated against actual TV hardware yet:

| Detector                                        | Trigger                                                                                        | Severity                        |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------- |
| `high-latency-focus-change`                     | input→focus latency                                                                            | Warning ≥100ms, Critical ≥300ms |
| `high-latency-visible-update`                   | input→visible-update latency                                                                   | Warning ≥100ms, Critical ≥300ms |
| `repeated-redux-dispatch`                       | same action type ≥2× in one interaction                                                        | Warning                         |
| `js-stall-during-interaction`                   | any captured stall                                                                             | Warning, Critical ≥150ms        |
| `repeated-network-request`                      | ≥2 equivalent requests in one interaction (streams ≥2000ms excluded)                           | Warning                         |
| `react-commit-overlapping-delayed-frame`        | commit span overlaps a delayed frame's span                                                    | Warning                         |
| `network-completion-followed-by-commit`         | a commit is the very next event after a network response                                       | Warning                         |
| `excessive-commits-during-rapid-focus-movement` | ≥3 commits across a rapid-focus burst (gaps ≤150ms)                                            | Warning                         |
| `repeated-selector-recomputation`               | same instrumented selector invoked ≥2× with unchanged inputs in one interaction                | Warning                         |
| `unstable-selector-reference`                   | a selector returns a new reference despite unchanged inputs, in a window with ≥2 React commits | Warning                         |
